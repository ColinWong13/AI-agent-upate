# The Agent Report — 技术文档

> 版本：v2.6.1 | 最后更新：2026-06-04

---

## 一、项目概述

The Agent Report 是一个 AI 行业情报聚合平台，自动追踪学术论文、行业动态与竞品报告，并通过本地 LLM 生成中文 AI 摘要。项目采用服务端渲染（SSR）架构，定位为个人/团队内部使用的轻量级情报工具。

**核心能力**：
- 自动爬取 6 个学术来源 + 5 个新闻 RSS 源
- 接入本地 LLM（Ollama）生成中文周报摘要
- 竞品报告 CMS（结构化内容管理）
- 用户系统（注册 / 登录 / 收藏 / 笔记）

## 二、技术选型与原因

### 2.1 后端框架：FastAPI (Python 3.11)

| 维度 | 选择 | 原因 |
|------|------|------|
| 框架 | **FastAPI** | 异步原生支持，适合爬虫并发；自动 OpenAPI 文档；类型提示友好 |
| ASGI Server | **Uvicorn** | FastAPI 官方推荐，轻量高性能 |
| 模板引擎 | **Jinja2** | 服务端渲染首选，与 FastAPI 生态高度兼容 |

**为什么不选 Django / Flask？**
- Django 过于重量级，ORM + Admin + 中间件栈对轻量情报工具过度
- Flask 缺乏原生异步支持，多爬虫并发需要额外插件
- FastAPI 的 `asyncio.gather` 让 6 个爬虫并发执行变得极简单

### 2.2 数据库：SQLite（默认）/ PostgreSQL

| 维度 | 选择 | 原因 |
|------|------|------|
| ORM | **SQLAlchemy 2.0 (async)** | 异步查询原生支持，与 FastAPI Depends 无缝集成 |
| 默认数据库 | **SQLite (aiosqlite)** | 零配置、零依赖，`start.sh` 一键启动 |
| 生产数据库 | **PostgreSQL 15 (asyncpg)** | Docker Compose 部署时使用，连接池 + 健康检查 |

**设计要点**：
- 通过 `USE_SQLITE` 环境变量切换数据库，代码无感
- 异步引擎与同步引擎并存，兼顾迁移脚本和后台任务
- 所有表启动时自动创建（`Base.metadata.create_all`）

### 2.3 AI/LLM 接入：Ollama + OpenAI 兼容

| 维度 | 选择 | 原因 |
|------|------|------|
| 默认 Provider | **Ollama** | 本地运行，零 API 费用，无数据泄漏风险 |
| 默认模型 | **qwen2.5:7b** | 中文能力强，7B 参数可消费级硬件运行 |
| 备选 Provider | **OpenAI 兼容 API** | 支持任何兼容 `/chat/completions` 的服务 |
| 超时 | 120s | 覆盖本地模型推理时间 |

**LLM 调用链路**：
```
digest.py → call_llm(prompt, system_prompt)
  → get_llm_config()  # 读取环境变量 / 数据库配置
    → Ollama: POST /api/generate (非流式)
    → OpenAI: POST /chat/completions
```
- 模块化设计，切换 Provider 只需改 `LLM_PROVIDER` 环境变量
- 配置优先级：环境变量 > 数据库 `system_config` 表 > 代码默认值
- 失败时自动降级为纯文本摘要，不影响服务可用性

### 2.4 爬虫系统

采用「并发执行 + 独立去重」架构，6 个学术爬虫 + 1 个新闻爬虫。

#### 学术爬虫

| 爬虫 | 数据源 | 方式 | 日期来源 | 备注 |
|------|--------|------|----------|------|
| arxiv.py | export.arxiv.org API | XML API | API 返回的真实日期 | 分 4 个分类抓取 |
| neurips.py | papers.nips.cc | Web 爬取 | 当前（待修复） | HTML 结构变化风险 |
| iclr.py | api.openreview.net | API | 当前（待修复） | 需更新会议年份 |
| icml.py | proceedings.mlr.press | Web 爬取 | 当前（待修复） | 依赖 CSS 选择器 |
| acl.py | aclanthology.org | Web 爬取 | 当前（待修复） | 依赖 CSS 选择器 |
| cvpr.py | openaccess.thecvf.com | Web 爬取 | 当前（待修复） | 硬编码年份 |

**去重策略**：arXiv 按 `title + published_date`，其余按 `title + source`

#### 新闻爬虫（news_crawler.py）

| 数据源 | 方式 | 日期来源 |
|--------|------|----------|
| 36氪 RSS | `xml.etree.ElementTree` 解析 | RSS pubDate |
| 量子位 RSS | 同上 | RSS pubDate |
| ArXiv CS.AI/LG/CL RSS | 同上 | RSS published_parsed |

**设计要点**：
- 完全采用 RSS 而非 Web 爬取（Web 页面多为 JS 渲染，可靠性差）
- 使用标准库 `ElementTree` 而非 `feedparser`（后者对中文 RSS 兼容性不佳）
- 日期解析支持 4 种格式：RFC 2822 / ISO 8601 / ISO-like / 纯日期
- 去重按 URL 唯一约束

### 2.5 前端设计

| 维度 | 选择 | 原因 |
|------|------|------|
| 渲染方式 | **服务端渲染 (SSR)** | 无需前端构建工具，SEO 友好 |
| CSS 方案 | **原生 CSS**（Newspaper 风格） | 零依赖，报纸风格设计语言 |
| 字体 | Google Fonts (Playfair Display + Lora + JetBrains Mono + Inter) | 报纸排版感 |

**设计语言**：Newsprint（新闻纸风格）
- 全局直角边框（`border-radius: 0`）
- 黑/白/红三色系统 + 纸张纹理背景
- CSS Grid + Flexbox 响应式布局
- Sticky 导航 + 毛玻璃效果

### 2.6 认证系统

- **JWT (python-jose)** + bcrypt 密码哈希
- 用户可选登录（`current_user` 返回 `None` 时不阻断）
- `require_user` 用于需要登录的接口
- Token 7 天过期

### 2.7 定时任务

- **APScheduler** (AsyncIO 调度器)
- 学术爬虫：每天一次（arXiv）/ 每周一次（各会议）
- 新闻 RSS：每 6 小时
- 周报生成：每周日 20:00（论文）/ 20:30（行业）

## 四、核心功能实现思路

### 4.1 AI 周报自动生成

**触发机制（双层保险）**：

1. **定时触发**（scheduler.py）：每周日 20:00（论文）/ 20:30（行业）通过 APScheduler 执行
2. **兜底触发**（main.py）：用户访问页面时检查 `latest_digest.week_end < today - 7d`，若过期则同步等待生成

**生成流程**：
```
1. 计算时间窗口（week_start = today - 7d, week_end = today）
2. 查询窗口内的 Paper/NewsItem（limit 100/50）
3. 若为空 → fallback 查询最新 100/50 条
4. 格式化论文/新闻列表为文本 prompt
5. 调用 LLM 生成 HTML 格式中文摘要
6. 保存 WeeklyDigest，设 is_latest=True（旧记录置 False）
7. 页面渲染时展示最新 digest
```

**容错设计**：
- LLM 调用失败时生成降级内容（含错误信息 + 统计数字）
- 旧周报自动进入「往期周报」折叠区
- `generate_news_digest` / `generate_paper_digest` 完全相同模式

### 4.2 爬虫并发执行

**学术爬虫触发**：
```python
# routers/paper.py
tasks = [_run(name, fn, results) for name, fn in crawlers.items()]
await asyncio.gather(*tasks, return_exceptions=True)
```
- 6 个爬虫并发执行，互不阻塞
- 单个爬虫失败不影响其他（`return_exceptions=True`）
- 返回各爬虫的 fetched/saved 统计

**新闻爬虫**：
```python
# crawlers/news_crawler.py
for source in RSS_SOURCES:
    items = await fetch_rss(source)
    all_items.extend(items)
    await asyncio.sleep(1)  # 礼貌延迟
```
- 5 个 RSS 源串行抓取（间隔 1s），避免被封

### 4.3 页面级 Digest 自动生成

```python
# main.py — 访问页面时同步生成（不创建后台任务）
stale = (
    latest_digest is None
    or latest_digest.week_end is None
    or latest_digest.week_end < date.today() - timedelta(days=7)
)
if stale:
    await generate_news_digest()  # 同步等待
    latest_digest = await db.execute(...)  # 重新查询
```

**为什么用同步等待而非后台任务？**
- 后台任务（`asyncio.create_task`）是发射后不管，用户刷新页面才看得到结果
- 同步等待确保页面渲染时 digest 已是新鲜内容
- 只在 digest 过期时阻塞（每周一次），其余时间页面秒开

## 七、已知问题与改进方向

| 问题 | 影响 | 计划 |
|------|------|------|
| 5 个学术爬虫使用 `date.today()` 而非真实日期 | 论文日期不准确，去重可能漏掉 | 解析各源站真实日期 |
| ICLR/CVPR 硬编码 2025 年份 | 新会议论文无法抓取 | 动态年份 / 手动配置 |
| 机器之心 JS 渲染无法爬取 | 缺失重要中文 AI 源 | 已替换为 RSS，持续扩充源 |
| CSS 选择器依赖特定 HTML 结构 | 站点改版导致爬虫失效 | 已全面切换 RSS |
| 无测试覆盖 | 重构风险高 | 补充核心流程测试 |
| 无 CI/CD | 手动部署 | 添加 GitHub Actions |
