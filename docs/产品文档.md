## 一、产品背景

### 1.1 为什么做这个产品

AI 行业发展极快，每天都有大量论文、新闻、产品发布。作为从业者，我们面临三个核心痛点：

1. **信息碎片化**：arXiv、NeurIPS、36氪、量子位……信息来源分散，每天切换多个平台效率极低
2. **筛选成本高**：海量信息中真正重要的不到 10%，但找到它们需要大量时间
3. **缺乏结构化视角**：竞品在做什么？行业趋势是什么？缺乏系统性的信息整理

### 1.2 产品定位

**个人/团队使用的 AI 行业情报聚合工具**，核心价值主张：

- **自动聚合**，不用手动刷各平台
- **AI 摘要**，用中文快速了解本周重点
- **结构化报告**，竞品分析不再是散落笔记
- **本地运行**，数据私有，零 API 费用

### 1.3 目标用户

- AI 行业从业者（产品经理、研究员、工程师）
- 需要追踪 AI 学术进展的学生/学者
- 关注 AI 赛道竞争格局的投资者/分析师

## 二、基础功能

### 2.1 学术论文追踪

**页面**：`/papers`

- 自动汇聚 **6 个顶级来源**：arXiv、NeurIPS、ICLR、ICML、ACL、CVPR
- **多维度筛选**：按来源（多选）、日期范围、关键词搜索
- **论文详情页**：标题、作者、摘要、PDF 链接
- **AI 周报**：每周自动生成中文论文摘要，涵盖研究方向、代表性论文、趋势观察
- **手动爬取**：一键触发全量爬虫，即时获取最新论文

**核心交互**：
```
论文列表 → 筛选/搜索 → 点击卡片 → 详情页 → 收藏/写笔记
                                      ↘ PDF 直达
```

### 2.2 行业动态追踪

**页面**：`/news`

- 聚合 **5 个 RSS 源**：36氪、量子位、ArXiv CS.AI、ArXiv CS.CL、ArXiv CS.LG
- **分类浏览**：行业资讯 / 学术资讯
- **AI 周报**：每周自动生成行业动态摘要，涵盖重大事件、趋势分析、公司动态
- **手动爬取**：一键获取最新资讯

**核心交互**：
```
动态列表 → 分类筛选 → 点击卡片 → 跳转原文
                             → 收藏
```

### 2.3 竞品分析报告

**页面**：`/report`

- **6 大章节**结构化报告：
  1. 核心概念与 Agent 原理
  2. 主流 Agent 平台深度对比
  3. 垂直领域 Agent 竞品分析
  4. 面向产品研发的 Agent Skills
  5. Claude Code 配置指南
  6. 总结与建议
- **CMS 后台**：支持通过 API 更新报告内容
- **数据迁移**：从旧版 HTML 自动解析导入（migrate.py）

### 2.4 用户系统

- **注册/登录**：邮箱 + 密码，JWT 认证
- **收藏**：论文和新闻均可收藏，统一管理
- **笔记**：论文可添加个人笔记
- **可选登录**：未登录用户仍可浏览所有公开内容

### 2.5 AI 周报系统（核心亮点）

**双层保险机制**：

1. **定时生成**（scheduler.py）
   - 论文周报：每周日 20:00 自动生成
   - 行业周报：每周日 20:30 自动生成
   - APScheduler 守护进程持续运行

2. **兜底自动生成**（main.py）
   - 每次访问页面时检查：`最新周报.week_end < 今天 - 7 天`？
   - 如果过期 → 同步等待 LLM 生成 → 渲染新周报
   - 如果新鲜 → 页面秒开，零延迟

**为什么这样设计？**
- 定时任务可能因服务重启、异常退出等原因漏执行
- 兜底机制确保「永远不会漏掉一周」
- 同步等待而非后台任务：用户第一次访问时就能看到新内容，而不是「刷新后才出现」

**容错设计**：
- LLM 不可用时：生成包含统计数据的纯文本摘要
- 数据库无新内容时：fallback 到最新条目
- 旧周报自动归档到「往期周报」折叠区

## 三、项目亮点设计

### 3.1 Newspaper 设计语言

整体 UI 采用「新闻纸」风格，与产品定位（情报聚合）高度契合：

- **字体系统**：Playfair Display（标题）+ Lora（正文）+ JetBrains Mono（代码/数据）+ Inter（UI）
- **色彩系统**：黑白红三色，灵感来自传统报纸排版
- **直角边框**：全局 `border-radius: 0`，强几何感
- **纸张纹理**：SVG 背景模拟纸面质感
- **交互反馈**：hover 阴影偏移（`box-shadow: 4px 4px 0px var(--fg)`），卡片微移动

### 3.2 零依赖快速启动

`start.sh` 一键启动脚本的设计理念：**clone 后 30 秒内看到完整产品**。

```
git clone → ./start.sh → 浏览器自动打开 → 产品可用
                    ↓
          自动创建 venv
          自动安装依赖
          SQLite 零配置
          自动导入报告数据
          预爬取 arXiv 论文
          健康检查
```

### 3.3 爬虫容错架构

- 6 个学术爬虫通过 `asyncio.gather` 并发执行
- 单个爬虫失败不影响其他（`return_exceptions=True`）
- 手动触发 API + 定时任务双重保障
- 新闻爬虫全面采用 RSS（Web 爬取不可靠）

### 3.4 LLM 接入的工程化设计

- **Provider 抽象**：Ollama / OpenAI 兼容 API 通过同一接口调用
- **配置热切换**：改环境变量即生效，无需改代码
- **本地优先**：默认 Ollama + qwen2.5:7b，数据不出本机
- **优雅降级**：LLM 不可用时页面功能不受影响

### 3.5 开发体验

- API 自动文档：FastAPI 自带 Swagger UI（`/docs`）
- 类型安全：Python 类型提示 + Pydantic 验证
- 数据库自动建表：启动即用，无需手动 DDL
- 环境隔离：`USE_SQLITE=true` 开发模式无需 PostgreSQL/Redis

## 四、未来规划

### 4.1 学术爬虫逻辑优化和新增

**现状问题**：
- 5 个非 arXiv 爬虫使用 `date.today()` 作为发布日期
- ICLR / CVPR 硬编码 2025 年份
- 部分 Web 爬取依赖特定 CSS 选择器

**优化方向**：
- [ ] 解析各源站真实论文发布日期
- [ ] 支持动态年份/会议版本配置
- [ ] 新增更多学术来源（EMNLP、AAAI、IJCAI 等）
- [ ] 爬虫健康监控与告警

### 4.2 更新行业动态源

**现状**：5 个 RSS 源（36氪、量子位、3 个 ArXiv）

**扩充方向**：
- [ ] 虎嗅、极客公园等中文科技媒体
- [ ] The Verge、TechCrunch 等英文媒体
- [ ] 公众号/博客 RSS 桥接
- [ ] 自定义 RSS 源配置（后台管理）

### 4.3 视频资讯自动读取

**目标**：加入浏览器自动操作能力，实现对视频资讯的自动读取和整理

**技术方向**：
- [ ] Playwright/Puppeteer 浏览器自动化
- [ ] YouTube / Bilibili AI 频道监控
- [ ] 视频语音转文字（Whisper）+ AI 摘要
- [ ] 视频资讯卡片化展示（当前 video-card 组件已就绪）

### 4.4 报告-学术-动态联动

**目标**：打通报告页和学术、动态页，实现自动化更新

**联动方向**：
- [ ] 竞品报告中引用最新论文自动链接
- [ ] 报告章节关联论文标签，自动推荐
- [ ] 行业动态自动更新报告中的市场信息
- [ ] 时间线视图：按时间轴展示论文 + 新闻 + 报告更新

### 4.5 其他规划

- [ ] 全文搜索（Elasticsearch / SQLite FTS5）
- [ ] 邮件/飞书/企业微信推送周报
- [ ] 多语言支持（英文界面）
- [ ] 移动端适配（PWA）
- [ ] 数据导出（BibTeX / CSV）
- [ ] CI/CD（GitHub Actions 自动测试 + Docker 镜像发布）
- [ ] 单元测试 + 集成测试覆盖
